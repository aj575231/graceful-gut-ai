# Phase 1F — infrastructure stack, authored but not applied

`template.yaml` is the administrator-controlled infrastructure stack for the
public entry point: a Regional REST API, an explicit stage and deployment, a
WAF Web ACL associated with that stage, an IP-free access log group, and the
Lambda resource-policy statements that let this API — and only this API —
invoke the application function.

**Nothing in this directory has been applied.** No AWS resource was created,
read, or modified to produce it. `administrator-runbook.md` records the create,
update, verification, and rollback procedures; it does not execute them, and
neither did the session that wrote it.

---

## What this stack owns, and what it must never own

| Owned here | Owned by the application path |
| --- | --- |
| REST API, resources, methods, models, request validator | Lambda code |
| Stage, deployment, throttling, access logging | `APP_ENV`, `GG_API_SECRET_ID` |
| WAF Web ACL and its association | Memory, timeout |
| Access log group and retention | **Reserved concurrency** |
| Lambda resource-policy statements for this API | |

The split is the point. If one template owned both the API and the function,
whatever could deploy the template could also rewrite the WAF association and
the resource policies — through CloudFormation rather than directly, but with
exactly the same effect. **Infrastructure as code changes how a privilege is
exercised, not whether it is held.**

Reserved concurrency stays deliberately on the application side, because
setting it to `0` is the emergency kill switch and must not wait for an
administrator. It is currently `2` and this stack does not touch it.

### The function is referenced, never managed

`ApplicationFunctionArn` is a parameter. The template declares no
`AWS::Lambda::Function`, no `AWS::Serverless::Function`, no alias, no version,
and no function-URL resource. A stack update cannot replace, reconfigure, or
delete the running application.

## Placeholder and parameter convention

Same convention as `infrastructure/README.md` and `infrastructure/phase1e/`:
values that must not be committed are supplied at apply time.

| Value | How it arrives |
| --- | --- |
| AWS account ID | never written down — `${AWS::AccountId}` resolves it in-stack |
| Region | `${AWS::Region}`; the deployment is pinned to `us-east-2` |
| REST API ID | generated by the stack, published as the `RestApiId` output |
| Production origin | `ProductionOrigin` parameter, supplied at deployment time |
| Development origin | `DevelopmentOrigin` parameter, optional |

`parameters.example.json` shows the shape of a parameter file with placeholder
values only. Copy it outside the repository, fill it in, and keep the filled
copy out of Git.

`backend/tests/test_phase1f_foundation.py` fails if a twelve-digit account ID,
a literal `execute-api` hostname, or a real domain reaches any file here.

## Why the SAM transform is declared but unused

`Transform: AWS::Serverless-2016-10-31` is present so the stack deploys through
`sam deploy` alongside the rest of the toolchain. Every resource is
nevertheless written as plain CloudFormation.

That is deliberate. This stack's safety property is that an administrator
reviews a change set before anything is applied, and a change set is only worth
reviewing if it corresponds to the file that was reviewed. With no
`AWS::Serverless::*` resources, the transform is a no-op and the processed
template equals the source, so the diff the administrator approves is the diff
in Git. Introducing an `AWS::Serverless::*` resource would silently end that
property — the transform would begin generating resources that appear in the
change set and nowhere in this file.

`AWS::Serverless::Api` was also rejected on its own terms: it manages the
deployment and stage implicitly, and this stack needs both explicit.

## Two design points that are easy to get wrong

### Body size is a WAF rule, not request validation

API Gateway request validation **cannot** cap body size — it validates against
JSON Schema, and JSON Schema has no body-size keyword. The 4,096-byte cap is a
WAF `SizeConstraintStatement`. The JSON Schema `maxLength: 2000` caps message
**characters**, which is a different measure: 2,000 multi-byte characters can
exceed 4,096 bytes. Three layers each do a job the others cannot, and the
application must check byte size and character length separately.

The size rule uses `OversizeHandling: MATCH`. A body larger than WAF's
inspection limit cannot be measured, so treating oversize as a match is what
makes the rule total — `CONTINUE` would let the very largest bodies through.

### `$default` is what closes the content-type validation gap

API Gateway **skips** body validation when no model matches the request's
content type, so a body sent as `text/plain` would reach the function
unvalidated. The model is therefore registered under both `application/json`
and `$default`.

`PassthroughBehavior: NEVER` is set as specified, and is inert on an
`AWS_PROXY` integration — passthrough governs integrations that use
`RequestTemplates`, and a proxy integration has none. Returning `415` for an
unsupported content type is the application's job on a proxy integration.
Recording this rather than assuming the setting works is the difference between
a control that exists and one that only looks like it does.

## Known gaps, carried forward deliberately

| Gap | Detail |
| --- | --- |
| WAF rate floor | AWS will not accept a rate-based limit below **100** per window. The ADR proposes 40 and 60 per five minutes for the chat route; neither is expressible. `MinValue: 100` makes this fail at validation rather than at apply time. A sub-100 effective limit needs API Gateway per-method throttling or an application-side counter. |
| Rate rules ship in `Count` | A rate rule in `Count` protects nothing. `WafRateRuleAction` must be `Block` before the education route carries public traffic. |
| Redeployment is a manual step | `AWS::ApiGateway::Deployment` is immutable; CloudFormation will not replace it when a method changes. Route changes reach callers only after `aws apigateway create-deployment`. |
| Account-level CloudWatch role | Access logging and execution logging need an account-wide API Gateway CloudWatch role. It is an administrator prerequisite and is **not** declared here, because `AWS::ApiGateway::Account` is a region-wide singleton and a stack delete would clear it for every API in the region. |
| Sampled requests retain IP | ~3 hours, not redactable, and the only way to review a count-mode rollout. No `AWS::WAFv2::LoggingConfiguration` exists, because WAF logs cannot omit client IP at all. |

## What this does not do

- It does not create infrastructure. Nothing has been applied.
- It does not enable public free-text input. `EnableEducationRoute` defaults to
  `false`, and turning it on does not by itself satisfy the `CLAUDE.md` release
  gate — the launch-blocking legal and model-provider determinations, and a
  real authentication decision to replace `X-GG-Key`, come first.
- It does not retire the Function URL. That is a separate administrator
  sequence with its own rollback, documented in the ADR.
- It does not create AWS Budgets.
- It does not audit `GracefulGutAI-LambdaExecutionRole`, whose attached
  policies remain unreadable from the dev role.
